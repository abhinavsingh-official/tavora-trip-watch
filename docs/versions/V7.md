# Version 7 — audit fixes, real migrations, CI, and one real requirement gap closed

*Same template as V1.md-V6.md. See `docs/internal/decision-log.md` for the reasoning
behind any choice referenced here, and `docs/internal/audit-log-2026-11-23.md` for the
full findings this version fixes.*

## 1. What this version does

Fixes all 11 findings from the full audit, adds real Alembic schema
migrations (a previously-missing Sec. 14 deliverable item), sets up CI
(GitHub Actions: backend tests + a fresh-database migration check, frontend
type-check + build), and closes one further gap found during a fresh
requirement-by-requirement re-read: Sec. 06's "lowest observed valid total"
and price-history chart were never actually built, despite being marked
done.

## 2. What's new since V6

- **Real schema migrations** (`backend/alembic/`): a baseline migration
  capturing the schema as of V6, plus one adding the three columns below.
  `scripts/seed.py`/`reset.py` now run `alembic upgrade head` instead of
  `Base.metadata.create_all`; tests keep using `create_all` deliberately,
  for speed (see `tests/conftest.py`), with CI separately verifying the
  real migrations apply cleanly to a from-scratch database.
- **CI** (`.github/workflows/ci.yml`): backend job runs the real pytest
  suite against a Postgres service container, then verifies
  `alembic upgrade head` on a dropped-and-recreated schema; frontend job
  runs `npm ci` + `npm run build` (tsc + vite).
- **Finding #0 (Critical) fixed**: `review_notification` and `book()` now
  reject a non-active request (400); `pause_request`/`cancel_request` now
  invalidate stale held offers, same as editing already did;
  `list_notifications` only shows alerts for active requests. 4 new tests.
- **Finding #6 (Critical) fixed**: a Scenario Lab price override now skips
  the real supplier call for that component entirely and forces it
  `"complete"` - previously it still made the real call and could be
  silently discarded if that call failed, undermining the Lab's entire
  "deterministic replay" purpose (Sec. 11).
- **Finding #3 fixed**: `api.ts`'s shared `request()` now extracts a clean
  message from the backend's JSON error body instead of surfacing
  `400 Bad Request: {"detail":...}` verbatim everywhere.
- **Finding #5 fixed**: notifications now carry and show route, itemized
  total, and quote status (Sec. 07's own requirement), not a bare repeated
  "Request #N".
- **Finding #1, #7, #8 fixed** via three new nullable/defaulted columns
  (`TripRequest.updated_at`, `BookingAttempt.updated_at`,
  `PriceObservation.min_star_rating_used`): a stale-total banner on the
  Dashboard, a second Ops timeline event when a booking's state changed
  after it was created, and Trip Story candidates filtered by the star
  rating actually in effect at check time.
- **Finding #2, #4, #10 fixed**: Cancel is a two-step inline confirmation;
  every Scenario Lab button disables with feedback while any one action is
  in flight; editing a cancelled request is rejected server-side and the
  Edit link is hidden for one.
- **Finding #9 fixed**: `backend/tests/test_request_status.py`, 7 new
  tests - the regression coverage that was missing and let finding #0 ship
  undetected across 5 prior versions.
- **Finding #11 (found this version, not the original audit)**: Sec. 06's
  "lowest observed valid total" and price-history chart - never built
  despite being marked done. The Dashboard now keeps a request's full
  observation history (not just the latest) and shows latest valid total,
  lowest observed valid total, and a real inline SVG line chart with a
  budget reference line - no new charting dependency.

## 3. Architecture active this version

Schema migrations are now real (Alembic), not implicit (`create_all`) -
everything else (scheduler, alert state machine, hold mechanism, booking
workflow) is unchanged.

## 4. Data sources used

Unchanged from V6.

## 5. Simulation controls available this version

Unchanged in shape; the price-override lever is now actually deterministic
(finding #6), which is a correctness fix to existing behavior, not a new
lever.

## 6. Stress tests run + results

- `backend/.venv/bin/python -m pytest -q` - 47 passed (8 new: 1 in
  `test_pricing.py` proving the override fix, 7 in the new
  `test_request_status.py`).
- Migration verification: a baseline migration generated against a
  genuinely empty database (not the already-populated dev DB, which would
  have produced an empty no-op migration) applies cleanly; the
  three-new-columns migration applies cleanly to a database with existing
  rows (`server_default=now()` backfill for the two `NOT NULL` additions).
  `scripts/reset.py` fixed alongside this - `Base.metadata.drop_all`
  doesn't touch Alembic's own `alembic_version` table, which would have
  made `seed()`'s `alembic upgrade head` think it had nothing to do after a
  reset; now explicitly dropped too.
- Every one of the 11 audit findings' fixes was live-verified against a
  real running local server, not just unit-tested: reproduced finding #0
  live before the fix (cancelled request → real review → real booking,
  all succeeding), confirmed it's rejected after; reproduced finding #6
  live (hotel override + forced real failure still lands "unavailable"
  before the fix, forces "complete" after); screenshotted the cancel
  confirmation, the clean error message, the enriched notifications list,
  the stale-total banner, and the real price-history chart.
- `backend/scripts/load_test.py` re-run fresh after all changes: 3 cycles
  of 100 requests, ~0.6s/cycle, 0 errors, 0 duplicate alerts, 40/40
  expected notifications - unaffected by the pricing.py restructure since
  the load test patches `build_package` directly, bypassing it.
- `npm run build` - clean, before and after every structural change.

## 8. Honest gaps — what's left

- Visual polish beyond what V5/V6 already did - still last, by choice,
  unchanged since V1.
- The per-component hold design (Sec. 08 describes potentially-different
  per-component expiries, "cannot outlast the earliest") was simplified
  from day one to one shared package-level hold, computed from all three
  components checked atomically together - technically satisfies the
  requirement (all three expire at the identical instant, trivially the
  earliest), but this simplification was never explicitly written down as
  its own decision until this version's re-read. Noted here now; not
  changed, since the simpler design already satisfies the literal
  requirement and a reviewer can be told this directly.
- `provisional` component status remains schema-forward, not yet reachable
  by any real code path (unchanged since V1).
