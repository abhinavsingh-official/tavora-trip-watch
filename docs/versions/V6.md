# Version 6 — homepage, trip story, color scheme

*Same template as V1.md-V5.md. See `docs/DECISIONS.md` for the reasoning
behind any choice referenced here.*

## 1. What this version does

Directly responds to feedback that V5, despite looking more like a real
product, still "felt like a calculator" - a single itemized total per
request, with no visible sense of a choice having been made among real
alternatives. V6 adds a real homepage, a per-request "trip story" view
that shows the real alternative flights/hotels a check actually found
(with the one that got used highlighted), and a warmer color scheme. No
pricing, monitoring, or booking logic changed - this is a presentation
layer over data the system already fetches and already stores.

## 2. What's new since V5

- **Homepage** (`/`): a real landing page - product intro plus a profile
  card per mock user (A/B/C), each showing their real seeded request(s),
  with a "View as User X" action that switches the mock user and enters
  the Dashboard. The Dashboard itself moved to `/dashboard`.
- **Trip Story** (`/requests/:id/story`, linked from every Dashboard
  card): shows up to 5 real outbound flights, 5 real return flights, and 5
  real hotels from the request's last check - not just the one price - as
  a card grid, with the cheapest eligible option in each group visibly
  marked "Picked". Cabs shown too, clearly labeled simulated.
- New backend module `app/story.py` + `GET /api/requests/{id}/story`:
  extracts these real alternatives from `PriceObservation.raw_sources` -
  the full raw Sabre/Hotelbeds response already stored on every check.
  Makes **zero new supplier calls** - this is a read of data already paid
  for and already fetched, not new monitoring.
- Warm accent color (`#d9622b`, a sunset-leaning orange) replacing the
  black/white palette everywhere - buttons, active nav state, the "Picked"
  badge, links.
- Emoji section markers (✈️ 🏨 🚕) in place of any imagery - deliberately
  not stock photos, so nothing implies a specific real hotel/airline photo
  next to what's still sandbox/simulated pricing.

## 3. Architecture active this version

Unchanged - no new tables, no schema change, no new dependency (frontend
or backend). `app/story.py` is a pure-function module with no side
effects; the new endpoint is read-only.

## 4. Data sources used

Unchanged. The trip story view surfaces more of the *same* real Sabre/
Hotelbeds responses V1 onward already fetched and stored - it does not
introduce a new source or a new real API call pattern.

## 5. Simulation controls available this version

Unchanged.

## 6. Stress tests run + results

- `backend/.venv/bin/python -m pytest -q` - 39 passed (7 new tests in
  `tests/test_story.py`, covering: sorting candidates cheapest-first,
  ignoring non-INR fares, handling missing/empty raw data, capping at 5
  candidates, EUR→INR conversion, and the minimum-star-rating filter -
  using fixtures shaped like the real Sabre/Hotelbeds response structures
  confirmed in `app/sources/*.py`, not invented ones).
- Real end-to-end verification against a real local check: confirmed the
  story endpoint's "Picked" flight/hotel exactly matches the price already
  stored on the observation (not just "the cheapest in this new list
  again" - the matching logic was checked against real numbers, not
  assumed correct from the code).
- `npm run build` - clean.
- Real headless-browser screenshots of the Home page, Dashboard, and Trip
  Story page, at both desktop and 390px mobile width - reviewed directly.
  Zero console errors across all three.

## 8. Honest gaps — what's left

- The trip story only reads the *latest* observation for a request, not a
  specific historical one - matches how the rest of the product already
  treats "latest" as the default view (Dashboard, Ops), not a new
  inconsistency, but noted since this version explicitly surfaces more
  historical-shaped data than before.
- No alternative-options view for a request that has never been checked,
  or whose last check came back `unavailable` - both show a plain "no
  options" message rather than a styled empty state illustration. Scoped
  out deliberately - still visual polish, not correctness.
